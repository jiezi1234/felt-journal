# P0 开发与验收

更新：2026-10-13。项目保持原生微信小程序 WXML / WXSS / JavaScript；原 `front/` 设计、HTML、截图及云开发示例文件保留。业务入口已由 QuickStart 改为五个页面：首页、毛毡板、记忆详情、时光回顾、导出预览。没有新增账户、同步或 P1/P2 功能。

## 运行方式

微信开发者工具导入项目根目录 `D:\xuexi\app\my_app`，使用既有 AppID，启动 `pages/index/index`。本地记录不需要云环境。现有私有配置使用基础库 3.17.3；选图优先 `chooseMedia`，兼容旧版 `chooseImage`。

手机尚未部署提取服务时，选取照片后会显示明确失败原因。点击“使用原图继续（保留矩形）”可以完成本地记录验收；该路径不代表真实主体提取完成。开发者工具现已接通本机真实模型服务，手机预览不使用回环地址。真实后端启动、调试与部署见 [backend/README.md](../backend/README.md)。

## 已实施的规则

- 共用 1500×1000 逻辑板体，3:2，外框深棕，内边距 45；位置基于内部毡面。三种底色：燕麦米、浅鼠尾草、暖灰。首页、浏览、编辑与 1800×1200 PNG 导出使用相同渲染器。
- 每次缩放 ×1.1 或 ÷1.1、旋转 15°；最长边限制 110–850 逻辑单位，变换后检查旋转包围盒及圆角安全距离。四角操作有效区域 44×44 屏幕像素、图标正向；采用独立原生按钮点击层，编辑器绘制控件面确保原生 Canvas 截图也清楚可见，导出不绘制任何编辑控件。
- 每板最多 30 件；文字可空，最多 1000 字符；分类为未分类、饮食、自然、出行、日常、心情。原图与主体/原图降级图分别复制到用户持久目录，不引用选图临时文件。
- Memory、Board、Placement 在单个同步存储快照中一并提交。写入失败不替换成功快照；板面与文字保留待恢复草稿，空间不足无法写草稿时明确提醒保持当前页面并重试。
- 添加和替换持有独立任务标识、目标日期，取消/离开后的异步结果不能提交；重复回调不重复添加。替换先取得并持久保存新图再提交引用，所属板、坐标、展示框尺寸、角度和层级不变，新图按原展示框等比适配。
- 删除先确认，再原子移除记忆与摆放；最后清理已进入删除队列且不再被任何记忆引用的应用内图片，不操作系统相册。启动只重试明确排队的删除，不再按“缺少记录引用”扫描删除照片，保留存储异常后的恢复机会；异常退出遗留文件可能继续占用少量本地空间。
- 月历周一开始；每天按添加时间和稳定 ID 排序，最多取两张物件预览，删除后补位；返回保持月份。历史空板读取不建数据、不能补记；未来日期不能进入，未来月份不能切换。
- 导出读取已成功保存的构图，不接受未保存草稿；任一照片缺失即提示失败，不能生成缺件的成功作品。生成成功与相册保存成功分别记录；相册拒绝可打开设置后重试。

测试临时隔离结构化存储，结束后恢复原值并删除测试所用文件；不能与手动编辑或代码热重载同时运行。`artifacts/` 包含模拟器截图、真实提取 PNG 和测试报告，属本地验收产物，不进入小程序包。

开发工具对原生 Canvas 的自动截图偶发超时，逻辑 E2E 默认不请求截图；需要重新采集时先设置 `$env:WECHAT_SCREENSHOTS='1'` 再运行，截图失败会独立报告。当前页面截图已经人工查看并用于修正按钮尺寸与控件显示。

## 真机验收清单（基础流程已收到用户通过反馈）

2026-10-13 用户完成两轮手机扫码并回复“都成功”“以上全部通过”。已确认：预览打开、拍照/选图新增、四角布置、彻底关闭重开恢复、文字分类保存、替换保留构图、取消保留旧图、删除后首页/板面/月历同步，以及系统相册真实写入。来源是用户报告，未提供机型及系统版本。以下仍是完整验收的逐项清单，不能把基础通过扩大为全部异常场景通过。

1. 确认照片/相机隐私授权与相册保存权限可申请、拒绝、恢复；拍一张照片，选择真实相册照片，分别完成单张添加。
2. 部署 HTTPS 提取后端并配置微信上传/下载合法域名，上传咖啡、食物、花束和复杂毛发照片，检查真实透明轮廓、细边缘、接触阴影及处理耗时。
3. 将物件拖到四边、四角，在最窄手机上点击四角控件多次旋转、缩放；确认无重叠遮挡、误开详情、越过内毡面或其他物件重排。
4. 修改底色、文字、分类；彻底退出并重新打开微信小程序，核对图片、位置、尺寸、角度、层级、所属日期完全一致。单纯 `reLaunch` 不替代设备重启与文件持久性验收。
5. 模拟无网络、处理失败、处理中取消、处理中退出、连续点击、低存储、照片文件缺失。确认已保存记录不丢失、无迟到插入、无重复项，保存失败能恢复或重试。
6. 在午夜前添加/替换/编辑，处理完成跨零点后仍归原板；返回首页显示新日期。已有历史板可编辑，历史空日期和未来日期不可添加。
7. 添加至少三件并替换/删除前两件，核对首页、详情、板面、月历同步与每日两张预览补位；跨年与闰年月份布局正确。
8. 从浏览导出完整 3:2 板面，核对四边框、底色、所有物件与构图一致，无工具、选中框和导航；实际保存到系统相册并打开图片核验清晰度与完整性。
9. 首次记录显示本地数据说明；清理/卸载风险可理解。全部通过后再勾选优先级文档的首版验收清单。

尚未实测的主要项：通过正式 HTTPS 的手机主体提取及用户照片质量、权限拒绝与恢复、低存储、跨零点，以及窄屏极限边角操作。关闭重开与系统相册成功写入已获得用户反馈，不再作为完全未验收项。
