# 照片自动分类

新增照片时，主体提取接口在同一次上传中返回分类。小程序直接保存分类，用户无需打开分类选择器。结果页使用“已保存 · 饮食”这样的短提示，详情里用“饮食 · 自动”区分自动结果。现有分类筛选直接使用保存后的分类。

## 分类规则与边界

- 自动范围为“饮食、自然、出行、日常”。“自然”包含动植物与自然景物，“出行”依据交通工具等可见物件，不根据风景推断旅行经历。
- “心情”不从照片推断，仍可由用户自选。
- 低把握、分类服务关闭/缺少模型/运行失败，均保存为“未分类”，不会要求用户补选，也不会影响已完成的抠图。原图回退不复用失败任务的分类。
- 手动纠正过的分类、旧版已有的非空分类，在替换照片时保留。未手动纠正的自动分类随替换照片重新判断。只改文字不会清除自动来源。
- 本次只处理新增或替换照片；不批量上传、修改已有记忆。用户没有分类动作也能完成记录。

这是一版轻量物件分类，不能保证所有照片正确。植物与蔬菜、容器和内容物、多主体、边缘物件及抽象场景容易混淆。置信分数用于拒绝含糊结果，不是准确率承诺。手动修改入口仍然保留。

## 本地模型

采用 [ONNX Model Zoo MobileNet v2](https://huggingface.co/onnxmodelzoo/mobilenetv2-12)，Apache-2.0 许可，权重约 14 MB。来源仓库说明见 [ONNX Model Zoo](https://github.com/onnx/models)。权重 SHA-256 固定为：

`c0c3f76d93fa3fd6580652a45618618a220fced18babf65774ed169de0432ad5`

模型在自己的服务器 CPU 上运行，不调用按次付费的图片识别接口。图片使用现有上传请求，服务器不会额外保存原图。ONNX Runtime 由现有 `rembg[cpu]` 依赖提供，推理线程数限制为 2。

输入保留原图中心正方形区域并缩放至 224×224，按模型 RGB 均值/标准差归一化；不额外放大中心区域，以减少生活物件被截断。将 1000 个 ImageNet 类映射为上述四类，同时检查最高细类分数、合并分数与前两类间隔，含糊结果不自动写入具体类别。映射与阈值见 `backend/classification.py`。

模型权重不进入 Git，也不在请求过程中自动下载。首次启用前执行：

```powershell
backend/.venv/Scripts/python.exe -m backend.prepare_classification_model --download
```

已下载的模型也可导入：

```powershell
backend/.venv/Scripts/python.exe -m backend.prepare_classification_model --model path/to/mobilenetv2-12.onnx
```

环境变量 `FELT_CLASSIFICATION=mobilenet-v2` 默认启用，设为 `off` 可关闭；`FELT_CLASSIFIER_MODEL` 可指定权重路径。默认文件位于 `backend/.runtime/classification/mobilenetv2-12.onnx`。导入会校验长度和 SHA-256，校验失败不会覆盖旧模型。

Docker 继续使用原来的运行数据卷。把模型传到服务器后，通过标准输入写入容器的 `/tmp`，再执行导入工具：

```sh
docker compose --env-file backend/.env -f backend/compose.yaml exec -T extractor \
  sh -c 'cat > /tmp/mobilenetv2-12.onnx' < /path/to/mobilenetv2-12.onnx
docker compose --env-file backend/.env -f backend/compose.yaml exec -T extractor \
  python -m backend.prepare_classification_model --model /tmp/mobilenetv2-12.onnx
```

`/health` 中 `classificationEnabled` 表示开关状态，`classificationLoaded` 只有完成首次成功推理后才为真。只有健康接口正常，不能当成分类已验证。

## 接口与兼容

`POST /extract` 保留 `cutoutUrl`、`expiresIn`，新增可选结果：

```json
{"classification":{"category":"饮食","confidence":0.79,"status":"classified","model":"mobilenet-v2"}}
```

`status` 还可能是 `uncertain`、`unavailable`、`disabled`，这些情况下不写入具体自动分类。小程序只接受白名单内、分数有效且状态为 `classified` 的结果；旧后端没有此字段也可照常保存。记忆增加可选 `categorySource` 字段，兼容原 v1/v2 数据，无需迁移或清空存储。

## 本机预览切换

当前电脑的 8787 端口仍是旧版调试进程。本轮后台重启及另起调试服务均被自动审批策略拒绝，未停止旧进程，也未修改开发者工具的连接地址。要在本机预览自动分类，可手动在项目根目录的终端启动独立服务：

```powershell
$env:FELT_MODEL='nosh-mnn'
$env:FELT_PUBLIC_BASE_URL='http://127.0.0.1:8791'
backend/.venv/Scripts/python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8791
```

保持上述终端运行，在另一个终端连接开发者工具：

```powershell
$env:WECHAT_EXTRACTION_ENDPOINT='http://127.0.0.1:8791/extract'
npm run dev:extraction
```

调试开关仍只作用于开发者工具，不改变手机或发布版配置。`WECHAT_EXTRACTION_ENDPOINT` 只接受 `127.0.0.1` 的有效端口与 `/extract` 路径；不设置时保持原来的 8787 默认值。切换调试地址期间不要运行其他模拟器自动化。
