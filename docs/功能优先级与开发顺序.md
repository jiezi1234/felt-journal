# 毛毡生活手账功能优先级与开发顺序

更新日期：2026-10-14

首版目标是让用户完成“选择照片 → 自动提取主体 → 在当天毛毡板布置 → 保存 → 查看详情与月历 → 导出到相册”的完整流程。先交付 P0，再按实际使用反馈推进 P1 和 P2。

优先级沿用[界面功能说明](./界面功能说明.md)，视觉与板体形态沿用[前端界面生成提示词](./前端界面生成提示词.md)。本表安排开发先后及验收条件；具体工期在明确开发资源和提取服务后补充。

## P0 首版必须完成

已有 `front/` 页面设计与 HTML 原型已作为实现依据。2026-10-13 已将 `miniprogram/app.json` 改为真实业务页面；本地记录、编辑、详情、月历、整板导出已落地，主体提取后端已完成本地真实模型验证，仍待 HTTPS 部署与微信合法域名配置。以下继续按真实业务能力验收，真机项目不以模拟器结果代勾选。

### 第一批 完成本地记录与保存

这一批的验收目标：选择一张照片，放到今日板，调整位置、大小和角度，保存后关闭小程序，再打开仍能看到相同记录和布局。

| 编号 | 功能 | 开发范围 | 前置依赖 | 完成标准 |
| --- | --- | --- | --- | --- |
| P0-01 | 小程序页面与导航 | 将现有页面落地为小程序页面和组件；接通首页、板面、详情、月历及子流程；适配安全区域 | 现有界面原型 | 页面可打开、返回路径正确，主要按钮有明确响应，缺失能力不显示虚假成功 |
| P0-02 | 数据模型与本地持久化 | 保存 Memory 记忆、Board 每日板、Placement 摆放关系；原图、主体图和结构化数据分别管理 | 无，可与 P0-01 同期推进 | 图片使用持久文件引用；记忆与默认摆放一并保存；重启后可读取，失败不覆盖已有记录 |
| P0-03 | 共用毛毡板与浏览 | 实体深棕圆角框、米色毡面、独立主体物件；统一内部坐标、尺寸、角度与层级 | P0-01、P0-02 | 首页预览、浏览和编辑共用构图；浏览点击进入详情，滑动不改布局；屏幕适配不重排物件 |
| P0-04 | 拍照与相册添加 | 每次选择一张照片；保存原图；锁定目标板和日期；加入默认摆放 | P0-02、P0-03 | 取消选择不产生记录；添加只新增一个物件，不改变已有物件；开发阶段可用原图或固定透明素材验证流程 |
| P0-05 | 板面编辑与自动保存 | 选中、拖动、四角按钮缩放与旋转、取消选中、基础毡面颜色、完成编辑 | P0-03、P0-04 | 只改变当前物件；按钮靠近边缘仍可点；主体不越过内毡面；变换后自动保存，失败保留内容并能重试；重启恢复最后成功布局 |

开发阶段使用原图或演示主体只用于验证本地流程。首版完成仍要求接通 P0-06 的真实自动提取能力。

### 第二批 接通主体提取和记忆管理

这一批的验收目标：用户上传自己的照片后，获得真实提取的主体并直接回到原板；随后可补充文字、替换照片或删除记忆。

| 编号 | 功能 | 开发范围 | 前置依赖 | 完成标准 |
| --- | --- | --- | --- | --- |
| P0-06 | 自动主体提取 | 接通真实处理服务；上传、提取、保存状态；基础边缘和接触阴影；重试、使用原图、取消 | P0-04、P0-05；可在第一批提前验证服务效果 | 成功直接插入原板并选中；保留原图与主体图；提取失败和保存失败分别反馈；取消后的结果不插入；重复回调不重复创建 |
| P0-07 | 记忆详情与内容管理 | 查看原图和主体、选填文字与分类、替换照片、删除确认 | P0-02、P0-03；替换照片依赖 P0-06 | 替换成功保留所属板和布局，失败保留旧内容；删除同步清除应用内对应内容，不影响系统相册原图；返回恢复原浏览或编辑模式 |
| P0-08 | 首页真实数据联动 | 今日板、空板引导、记录数量、最近记录、记录或继续布置入口 | P0-02、P0-03；随添加和管理流程接入 | 数据来自真实记录；首次添加、编辑、替换、删除后预览同步更新；加载中与空状态区分；跨零点返回首页展示新日期 |

自动提取服务的可用性应在第一批期间提前验证，包括常见照片的主体效果、处理时间及失败响应，避免到第二批才发现服务无法满足产品需要。服务未选定时，先固定可替换的接口边界，不把演示结果视为完成。

### 第三批 完成回顾导出和首版验收

这一批的验收目标：用户能从月历找回某一天，并把与屏幕构图一致的完整毛毡板保存到手机相册。

| 编号 | 功能 | 开发范围 | 前置依赖 | 完成标准 |
| --- | --- | --- | --- | --- |
| P0-09 | 月历回顾 | 当月七列日历、月份切换、回到当月、每日最多两个物件预览、打开整板 | P0-02、P0-03；数据结构稳定后可提前开发 | 预览稳定排序；删除后按规则补位；返回保留月份；过去空日期仅浏览且不创建记录；未来日期不可进入；跨年和闰年正确 |
| P0-10 | 完整板面导出与保存相册 | 从已保存构图生成作品、预览、保存到相册及权限反馈 | P0-03、P0-05 | 保留完整深棕框、毡面和全部物件的相对位置、尺寸、角度及层级；无编辑控件；区分生成成功与相册保存成功；失败可重试；空板不可导出 |
| P0-11 | 异常与数据一致性 | 保存失败、文件缺失、空间不足、权限拒绝、处理取消、重复提交和跨日期处理 | 随 P0-02 至 P0-10 实施 | 不误报成功、不丢失已保存内容、不重复插入；跨零点仍写入原目标板；临时清理不删在用图片；首次保存显示本地数据提示 |
| P0-12 | 真机完整流程验收 | 验证页面适配、交互、存储恢复、真实照片处理、月历和导出 | 全部 P0 能力 | 在实际手机上完成下方首版验收清单；阻断主流程、造成数据丢失或状态错误的问题已修复 |

异常处理随各功能同步实现，P0-11 是集中核验项。每项功能完成时就应具备对应的失败与恢复路径。

### P0 首版验收清单

- [ ] 选择真实照片后能自动提取主体，直接放到发起添加的原板并选中。
- [ ] 提取失败可重试、明确选择使用原图或取消；取消后没有延迟插入。
- [ ] 新增、拖动、缩放、旋转和换毡面颜色能保存；关闭后重开图片与布局仍一致。
- [ ] 保存失败保留可恢复内容，不能误显示已保存。
- [ ] 浏览不会误改布局，四角操作按钮可点，窄屏下不被裁掉。
- [x] 文字和分类允许留空；替换图片不丢布局，失败不丢旧图；删除有确认。（自动测试及用户第二轮真机反馈）
- [x] 首页、详情、板面和月历引用同一条记忆，新增、替换和删除后同步刷新。（模拟器及用户真机反馈）
- [ ] 月历每日最多两个物件；点击日期看整板；历史空日期不生成新数据、不提供补记。
- [ ] 添加和替换过程中跨零点、取消或重复回调均不会串日期或重复创建。
- [x] 导出包含完整板框，构图与板面一致，无页面工具，能真实保存到相册。（实际 Canvas 导出、截图检查及用户真机反馈）
- [ ] 权限拒绝、文件缺失、空间不足和处理失败有可理解的反馈。
- [ ] 首次成功记录显示本地保存提示，用户知道清理相关数据可能导致记录丢失。

**全部 P0 通过验收后，才进入首版交付。** 自动提取、月历、导出与相册保存均属于 P0。

## P1 核心体验增强

P0 稳定后按下表顺序评估；具体取舍结合用户使用反馈。

已实现 **P1-01 至 P1-07** 的全部开发接入，包括主题板、跨板复用与仅移除摆放。95 项自动测试、8 页路由、官方模板编译，以及主流程、分类、分享、主题四组模拟器验收通过。主题板支持创建、重命名、删除和跨日期选取已有记忆；照片文字共用，板上布局分别保存。“仅移除摆放”保留记忆，详情“彻底删除记忆”清除所有板上的引用。旧数据只读兼容，首次成功修改才提交内部 v2 快照。

布局撤销最多 30 步，板面支持 6 色 × 3 纹理，分类查找每页 20 件，每块板最多 30 件，主题最多 50 块。微信分享使用当前预览的完整整板图片，相册保存状态独立。模拟器的分享、相册和确认框使用接口替身；实际发送、接收方查看、新交互及异常场景仍待真机。详细范围见 [P1开发与验收](./P1开发与验收.md)。下一阶段集中完成真机验收与 P0 正式 HTTPS 部署；P2 保留为后续评估项，当前不标记首版全部验收完成。

| 建议顺序 | 功能 | 用户价值 | 前置条件 |
| --- | --- | --- | --- |
| P1-01 | 撤销与重做 | 降低误操作成本，放心调整板面 | 编辑与保存稳定，明确哪些操作可撤销 |
| P1-02 | 手动置顶与置底 | 处理物件遮挡，完善自由构图 | 现有图层顺序能持久化并正确导出 |
| P1-03 | 手动裁剪与基础图片修正 | 改善自动提取不理想时的结果 | 原图、主体图、替换和回退流程稳定 |
| P1-04 | 更多毡面颜色与纹理 | 增加个性化选择 | 浏览、编辑与导出能一致渲染 |
| P1-05 | 分类筛选 | 更快找回某类生活记忆 | 分类数据和历史查询稳定 |
| P1-06 | 微信直接分享 | 降低分享作品的步骤 | 导出稳定，明确分享内容和落地页 |
| P1-07 | 主题板、跨板复用与仅移除摆放 | 同一记忆可用于多个主题，移除物件时可保留记忆 | 扩展记忆与板面的关联规则，重新定义删除和移除的区别 |

## 当前开始执行的任务

第一至第三批中不依赖部署与真机设备的开发已实施。首个节点已在微信模拟器完成：本地照片文件 → 原图降级明确确认 → 今日板 → 四角调整 → 保存 → reLaunch 后记录与构图一致。已继续实现详情、月历与实际 Canvas 导出；完整手机关闭重开和真实服务网络接通仍需验收。
