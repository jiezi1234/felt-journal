# 毛毡生活手账｜用户市场与产品调整调研

> 调研日期：2026-10-14（Asia/Shanghai）  
> 对象：当前微信小程序的用户机会、竞争与替代、功能取舍、市场验证路径。  
> 基线：现有产品需求、首页/板面/详情代码，以及技术可行性报告。  
> 状态：桌面研究已完成；用户访谈、真实留存、付费和获客实验尚未开展。本文是产品调整建议，不修改原需求或业务代码，不自动授权开发、投放、收费或联系用户。

## 1. 直接判断：有可识别的细分需求，当前产品的市场尚未被验证

**值得做小规模真实用户验证，但不建议按当前功能清单继续扩展后直接面向大众推广。**

公开资料支持“有人需要可爱手账、照片拼贴和生活回顾”，也证明竞争已经存在。它们不足以证明“毛毡板形式＋微信小程序＋每天手动布置”能让一群用户持续使用、替代原工具或付费。

| 判断 | 当前结论 | 证据 / 置信程度 |
| --- | --- | --- |
| 品类是否有人使用 | 有。中国区成熟手账产品有较多累计评分，海外有成熟拼贴工具 | M01–M03；事实，高；评分不能换算成活跃人数 |
| “照片抠图→贴纸日记”是不是空白市场 | 不是，已经找到高度相似的产品描述 | M04；事实，高；其商业成功未知 |
| 毛毡审美是否被目标用户明确需要 | 未验证。它目前是视觉特色，不是已证明的购买理由 | 项目定位事实＋市场假设，低至中 |
| 微信小程序是否比 App 更适合这群人 | 快速尝试/微信分享有合理机会；长期归档和回访是否更好未验证 | 产品形态判断，中；缺少本产品真实渠道数据 |
| 当前流程能否带来持续记录 | 有机会，但入口、手动排版、历史补记和可靠保存存在阻力 | L02–L05＋R01–R05；推断，中 |
| 是否已有明确商业市场 | 没有足够证据；竞品定价不是本产品付费意愿 | 未获本产品付费/复购/成本数据，低 |
| 是否值得继续 | 值得做一个范围收敛的验证版本；先证明第二次、第三次使用 | 综合建议，中，须用第 8 节实验更新 |

**建议优先验证的定位：给经常拍日常照片、想做可爱生活记录、但不愿学习排版的人，一分钟左右做出一张自己的照片贴纸收藏板。**

这里“一分钟”是待验证的体验目标，不是当前已达到的性能承诺。照片主体保留真实样貌，文字可选，系统先提供好看的默认构图，用户想布置时再微调。毛毡可作为默认视觉特色，先验证其偏好，不把整个产品的价值只押在一种材质上。

本报告按“先获得真实用户与持续使用，再决定商业化”作为工作假设；用户尚未确认项目优先目标。若主要用于课程/比赛，可保留较多展示型功能，但不能据演示成功推断市场成立；若要求尽快盈利，需要更早验证付费和单位成本。

## 2. 调研方法与可信边界

### 2.1 已完成的工作

- 阅读当前产品文档、技术报告，复核首页、板面、详情、导出与相关配置，判断真实实现和入口。
- 检索中文手账/照片拼贴产品、自动抠图日记、微信相关产品和系统替代能力。
- 核对 App Store 原始产品页、公开评论页、开发者官网，以及 Apple、Canva、美图、Day One 的官方资料。
- 将公开事实、用户评论个案、产品判断与待验证假设分开记录；不把开发者宣传语当成用户调研结果。

### 2.2 不能由本轮推出的结论

没有取得本产品 MAU、留存、用户画像、收入、转化、微信搜索量或可靠的同类小程序活跃数据。没有开展真实访谈，也没有实机试用全部竞品。因此不提供虚构的市场规模、市场份额、“年轻女性占比”或预计收入。

评分是指定商店/地区/页面展示的累计评分，可能经过四舍五入，且受运营和评价选择偏差影响；不是下载量、去重用户数、DAU/MAU、付费人数或自然需求占比。中国区和英国区评分也不能直接横比或相加。

公开评论页展示的是被平台选出的样本，包含旧评论、低信息内容和重复展开文本。尝试 Apple 最近评论 RSS 后，返回 feed 元信息而无评论 entry，**未取得可系统抽样的最新评论集**。本文只用明确可读的少量评论生成访谈假设，不声称做了“全网情感分析”或“某百分比用户要求某功能”。

证据标记：**事实/高**表示能在对应页面或代码中核对；**推断/中**表示由证据形成的产品判断；**待验证/低**表示需要真实使用或实验。M 为外部产品资料，R 为评论个案，L 为本地证据，链接见第 11 节。所有外部资料查阅日为 2026-10-14。

## 3. 竞争和替代：真正要争夺的是哪一种任务

### 3.1 竞争图谱

| 产品 / 范围 | 本轮可确认的公开事实 | 对当前产品的竞争含义 | 证据边界 |
| --- | --- | --- | --- |
| 念念手帐 / 中国区 | 页面显示约17万评分、4.7；有图文拼贴、贴纸/模板及会员权益 | “可爱＋生活记录＋素材”是成熟竞争方向 | M01，事实高；没有实际活跃/收入数据 |
| 时光手帐 / 中国区 | 页面显示约35万评分、4.9；有素材、一键图片排版及回顾相关能力 | 大而全手账和便捷排版已有供给 | M02，事实高；不由此推断本小程序能分到用户 |
| Shuffles / 英国区 | 页面显示约1.3万评分、4.6；支持抠图、图层、旋转缩放和拼贴 | 自动抠图与自由摆放不是独占能力 | M03，事实高；海外使用行为不直接代表中国微信用户 |
| 贴纸日记—AI写日记·照片手账 / 台湾区 | 开发者描述包含本机抠图、贴纸、日历/月回顾与分享；页面评分不足 | 与本项目核心路径高度重合 | M04，功能声明高；效果、规模、留存与盈利未验证 |
| Petanote / 官网 | 宣传照片＋一句话自动生成手账；FAQ称开发/内测准备、定价未定 | 表明其他团队也在争夺“不会排版也能记录”的任务 | M05，事实高；页面有下载入口与内测说明差异，不能视为成熟成功案例 |
| 拾片 / 中国区 | 照片碎片拼贴、回看/分享；页面约11个评分，并列会员购买项 | “照片重新组织成记忆作品”有具体产品形态 | M06，事实高；样本小，不能证明大市场 |
| Dakku 贴纸日记 / 中国区 | 撕贴纸、胶带、照片拼贴、日历和分享；更新记录含保存去广告调整 | 其定位强调制作过程与触感，效率不是唯一竞争维度（推断） | M07，功能/定位事实高；真实用户偏好和改动效果未验证 |
| Canva可画 / 中国官网 | 提供拼贴/网格模板、文字、贴纸与下载分享 | 若用户只要出一张图，通用设计工具即可替代 | M08，事实高；实际移动端步骤需任务测试 |
| 美图 / 官方网页 | 提供拼图、抠图与模板 | 单点“自动去背景”很难形成独立理由 | M09，事实高；未假定所有功能免费或移动端一致 |
| Apple照片 / 原生能力 | 支持在兼容 iPhone 上提取照片主体并复制/分享 | 对部分用户，做一张抠图贴纸已无需新工具 | M10，事实高；不意味着小程序可以调用同一底层接口 |
| Day One / 官方方案 | 强调记录、回顾、隐私、备份/导出；有免费及付费层 | 长期日记的信任和找回能力也会参与竞争 | M11，事实高；其用户与本产品目标并不完全相同 |

这里只比较本产品相关任务，不把所有功能罗列成“必须跟随”的清单。成熟竞品规模说明品类不是凭空想象；相似新产品的出现说明差异化压力；**两者都不是本产品 PMF 的证据**。

### 3.2 按用户要完成的任务判断

| 用户当下任务 | 现有替代 | 本产品必须多提供的价值 | 判断 |
| --- | --- | --- | --- |
| 留下一张照片 | 手机相册、微信收藏、系统笔记 | 更容易回看、比相册更有个人故事 | 仅复制照片不足以吸引迁移；推断中 |
| 快速发一张好看的图 | 拼图模板、修图/设计工具 | 从自己照片到满意成品更省步骤，风格更稳定 | 最适合低成本做直接对照实验；推断中 |
| 认真做复杂电子手账 | 成熟手账工具、平板手绘 | 必须有更强素材/笔刷/排版自由 | 当前按钮编辑与小程序形态不宜正面对抗；推断中 |
| 长期安全保存人生记录 | 相册备份、日记 App | 可恢复、可迁移、找得到、隐私可信 | 当前纯本地＋仅图片导出不足以支撑强长期承诺；L05，高/中 |
| 收藏日常物件并获得满足感 | 相册、拼贴、实体手账 | 自己的照片变成可辨认物件，轻松组合、积累与回看 | 这是最值得验证的细分任务；待验证低中 |

**商业机会更可能来自把整个任务做好，而不是拥有某个抠图算法。** 能否形成优势，取决于完成速度、默认成品质量、个人素材积累、稳定回看和低门槛再次使用。此为产品推断，中置信度。

## 4. 用户市场：先按行为分群，再谈年龄性别

目前没有可靠数据证明“某年龄段女性”就是本项目用户。建议以真实行为筛选，人口属性仅作记录与后续比较。

| 用户群 | 触发场景与真实任务假设 | 当前适配程度 | 首轮取舍 / 需要验证 |
| --- | --- | --- | --- |
| **轻量生活记录者**：经常拍食物、咖啡、小物，没稳定写日记习惯 | 今天有一两件值得留下的小事，不想写长文或研究排版 | 高，但手动编辑可能妨碍 | **第一优先招募**；是否愿在不同日期重复记录 |
| **周末/出游记录者**：已有一组照片，偶尔整理/发图 | 想把一次经历变成一张作品，之后找回 | 中；主题复用已有，但补记/多照片流程不顺 | 第二候选；应看下一次事件再用，不用日活苛求 |
| 宠物/玩具/文具等收藏记录者 | 反复拍同一对象，喜欢个人素材和主题收藏 | 中；跨板复用匹配，毛发提取有技术风险 | 小组测试，不先增加成长统计等垂直系统 |
| 重度手账作者/内容创作者 | 追求复杂审美、精细控制和高质量批量输出 | 中低；已有多工具习惯 | 用于设计反馈，不作为唯一首发目标，避免被引向大编辑器 |
| 长期档案型日记用户 | 希望多年记录不丢、全文搜索、迁移 | 当前偏低 | 先补恢复能力再承诺；不是靠可爱界面就能争夺 |
| 亲子/家庭长期记录者 | 保存重要成长时刻、多人查看 | 当前偏低；高留存、隐私/共享要求高 | 暂不主打，不因此立刻添加家庭协作 |

分群结论是 **M01–M11、评论与当前能力共同支持的市场假设，中至低置信度**。第一轮可优先招募18岁以上微信常用者，过去两周实际拍过至少6张日常照片，有过“想整理却没做”的经历；这是招募条件，不是已证实的用户人口分布。

### 4.1 推荐先用一个窄场景切入

首轮宣传和示例可围绕 **食物、咖啡、小物件的日常收藏**。原因是与现有“主体物件”模型相合、潜在重复频率较高、较容易说明第一次要记录什么；这些优势是推断，必须用同一测试验证，不能把复杂食物、透明杯子都预设为容易抠图。

周末/出游可作为第二套招募文案和模板测试。风景、多人合照、票根上的信息常需要保留背景，不能强迫所有照片都变成透明主体。宠物毛发需先满足质量门槛，避免用最难的样本作为首发唯一宣传承诺。

不要同时扩展成探店评分、卡路里、宠物健康或旅行攻略系统；这些是不同任务，会稀释当前验证目标。

### 4.2 用户为什么换工具、为什么回来

| 环节 | 需要成立的理由 | 当前缺口 |
| --- | --- | --- |
| 第一次打开 | “这张图是用自己的普通照片做的，我也能做到” | 空板占比高，未证明默认成品让新手满意 |
| 第一次完成 | 少量选择即可得到愿意保留的作品 | 逐张添加、默认同位置叠放、需理解编辑工具 |
| 第二次记录 | 添加入口始终好找，几秒就能开始 | 有记录后主按钮从“记录”切成“布置” |
| 一周后回看 | 看到时间和事件，想起发生过什么 | 月历能找日期，但照片的文字语境多藏在详情 |
| 长期保留 | 不担心换机/清理后全部消失，有恢复办法 | 本地文件容量有限，作品 PNG 不是可恢复备份 |
| 推荐给朋友 | 成品有辨识度，朋友也能快速试 | 导出已有；传播→打开→首次完成尚无真实数据 |

上述缺口来自 L01–L05 的事实；对留存的影响是推断，中置信度。

| 用户肯定可爱画风，同时对看视频解锁有保留 | R05：念念手帐，2021-02-09 | 素材有吸引力，但中断主流程的商业化要谨慎 | 不意味着所有用户拒绝广告或愿意付订阅 |

还观察到部分公开评论文字与产品关系很弱。本文排除其作为需求依据，这也进一步说明累计评分不适合直接估算市场规模。

## 6. 当前功能应如何修改：按用户价值排序

### 6.1 保留、优化、增加、延后

| 处理 | 功能 | 原因与证据 |
| --- | --- | --- |
| **保留** | 毛毡质感、真实照片物件、自动提取、直接回原板 | 是当前最清楚的体验组合，适合先测吸引力；L01、M04；推断中 |
| **保留** | 文字可留空、月历、主题复用、独立布局、导出 | 分别支持低负担、回看、个人积累和作品拥有；L01/L03、R01/R02；中高 |
| **保留并简化曝光** | 四角变换、撤销/重做、图层、裁剪 | 已有实现，不用删除；让愿意编辑的人使用，不把理解全套工具作为首记条件；L02/L03，中 |
| **先优化** | 首页/板面添加入口、默认摆放、保存/提取质量 | 最直接影响第一次与第二次完成；L02–L05，事实高/价值判断中 |
| **先测试再增加** | 少量场景模板、自动排版、照片样式切换、画面上一句话 | 解决结果好不好看、照片是否适合抠图、作品是否有语境；M02/M04/M08、R01，中 |
| **提前验证** | 历史补记/照片日期选择、小批量添加、可恢复备份 | 解决真实照片不都在当天整理和长期信任；现有需求明确没有这些，应先作为变更提案验证；中 |
| **后置** | 更多纹理、复杂修图/笔刷、AI长篇日记、徽章与连续打卡 | 尚无本产品用户证据；可能增加成本或记录负担；推断中 |
| **暂不进入** | 社区、多人协作、商城、饮水统计、泛生活助手 | 引入新任务与治理，不解决当前激活/留存核心问题；范围判断中高 |

已经实现的 P1 不因为“后置”而自动删除。建议减少首页和首次流程的认知负担，保留详情/更多操作中的可发现路径，先观察使用证据。

### 6.2 第一组：先让人愿意完成第一次

#### A01：主入口始终指向记录，而非完成后的编辑

**当前事实**：首页有照片后显示“继续布置”；对应 JS 进入编辑而不自动开选图。板面拍照/相册按钮位于外观设置区域之后。（L02，高）

**建议**：首页主按钮始终为“＋加一张照片”或“＋记录一件小事”；“查看/继续布置”做次入口。板面编辑中把添加照片放在画布附近或固定操作区；颜色纹理收进可展开设置。保留现有四角按钮，不重新引入已取消的底部滑杆。

**成功标准**：首次和有记录两种状态下，新用户无需口头提示可找到添加入口；比较找到入口时间和第二张添加率，而非只问界面是否好看。小型可用性实验可先于所有新增功能。（建议，中高）

#### A02：系统先排好，微调是可选项

**当前事实**：默认新物件使用相同中心位置，连续添加可能重叠；用户以拖动/按钮自己布置。（L03，高）

**建议**：先做3种轻量构图，例如“日常三件”“咖啡和小物”“周末片段”，不从海量模板起步。新增照片默认找不遮挡的空位，只改变新增物件；已有布局保持。用户明确点“帮我排好”才重排整板，并可一步撤销。可用确定性几何规则实现，不必先引入大模型排版。

**验证**：同样3张真实照片，现有默认布局与自动构图各做一次任务，顺序交叉；记录达到满意结果所需时间、手动调整次数、作品选择与理由。若用户反而喜欢自由制作，应保留空白/自由入口，不强制自动构图。（假设，中）

#### A03：允许保留完整照片，别把所有照片当成物件

**建议**：区分“主体贴纸”和“完整照片小卡”。人物合照、风景、菜单、票根可主动选完整照片；自动提取失败后的“使用原图”仍须明确是降级，不能改成假成功。样式切换应先确认视觉结果，再替换引用。

这会把当前失败兜底提升为有意的创作选择，但不需要首版上复杂蒙版笔刷。目标是保留照片中的故事，而非提高“所有照片都抠了图”的比例。建议依据 M04/M08 和照片任务分析，中置信度；具体采用率待验证。

### 6.3 第二组：让用户有理由第二次回来

#### A04：补记按真实生活发生时间组织

当前 P0 不允许历史空日期补记；现有主题板主要从记忆库复用，不能直接当作任意过去事件的照片入口。（L01/L03，高）

建议优先验证“今天添加、归到实际那一天”的显式日期选择。照片 EXIF 只作建议，不静默决定日期；无日期、截图、跨时区或旧照片让用户确认。每日板依然按日期组织，主题板可收集多日。首次先用最近7天作任务测试，但不要未经产品确认就把7天设为永久业务上限。

这是对现有 P0 范围的明确变更建议，需更新日期授权、任务目标锁定、未来日期和取消规则后再开发；不是一句“改日期”就完成。若访谈发现用户几乎都实时记录，可后移。（假设，中）

#### A05：回顾从“找到日期”升级为“想起事件”

保留当前月历每格两个物件的规则；增加可选的一句板面标题/短便签，在作品和最近记录里提供语境，例如“第一次自己做饭”。先采用简单固定位置样式，不扩成文字图层编辑器；Memory 详情仍保存更长文字。

在用户已有至少两周记录后，测试“本周收藏”或“这个月的几件小事”的本地汇总入口，默认私有、用户选择内容后导出。先做确定性回顾图，不把 AI 自动写人生故事当必要条件。回顾的成功指标是主动打开旧记录或再次创作，不是弹窗曝光量。（R01、M11；推断中）

#### A06：长期记录的恢复能力应早于大量装饰

纯本地数据和照片容量限制已在技术报告确认。当前作品 PNG 只能保留合成图，不能恢复原图、文字、分类和独立布局；“重要作品请导出”不等于可迁移日记。（L05，高）

内测可先明确风险并只用非唯一副本测试。若定位为长期生活档案，公开承诺前应验证一种真正可恢复的备份方案：手动导出/导入含素材和元数据的备份，或用户主动开通的云备份。先验证文件传递、容量、隐私和恢复，再决定方案；不直接增加完整多设备同步或强制账号。

市场建议是提高“可恢复”的优先级，技术上仍需 PoC、预算与产品确认。它改变此前纯本地 P0 的范围讨论，不能在未批准时写成已决定的业务需求。（建议，中高）

### 6.4 第三组：让作品更适合拥有和分享

#### A07：在固定板面之外提供分享排版

保留3:2编辑板及原版导出。测试将整板等比放入3:4或正方形卡片，外围可选日期/标题；不是修改原 Placement 或强行裁切。比例选择是实验方案，**不是小红书/朋友圈的强制规范**。

现有作品图片分享已接入，真正的发送与接收仍待真机验收。用户是否公开分享应自愿，不把私人回看用户算作流失。界面触发分享/保存成功不能当作发布到社交平台或朋友送达。（L04/L05，高；传播价值假设中）

#### A08：少量多照片添加，先测价值再做队列

旅行/周末场景可测试一次选3张，不直接放开30张批处理。每张独立显示成功/失败，保存已成功项；目标板锁定，避免一个失败导致整批丢失。需要串行或受控并发、幂等和取消设计。

若观察到用户主要每日一张，则保持单图即可；若主要是事件整理，再把小批量提前。不要为了“功能看起来完整”先付出整套任务队列成本。（假设，中）

### 6.5 建议调整的优先级与粗略成本

以下是调整的新增工程量级，1人日=8小时；不是已授权开发排期，不能直接加到技术报告总工期，因为质量、恢复、测试会重叠。设计稿、服务可用及范围明确为前提，估算置信度中低。

| 顺序 | 调整项 | 工程量级 | 先验证的东西 |
| --- | --- | --- | --- |
| 0 | 正式提取质量、保存/容量与真实手机链路 | 沿用技术报告 PoC，不能拿市场实验替代 | 参与者能成功用自己的照片完成任务 |
| 1 | A01 添加入口与设置折叠 | 1–2人日 | 找入口和再次添加更容易 |
| 2 | A02 少量默认构图、显式自动排版与撤销 | 3–6人日 | 满意结果更快，原布局不被误改 |
| 3 | A03 贴纸/完整照片样式选择 | 2–4人日 | 真实照片适配与质量接受度 |
| 4 | A07 分享卡片日期/标题和画幅包装 | 2–4人日 | 用户愿保存/分享，构图不被裁掉 |
| 5 | A04 显式补记 | 3–5人日 | 用户实际有过去日期的记录需求 |
| 6 | A05 简单标题/回顾 | 2–5人日 | 多日使用后确实主动回看 |
| 条件项 | A08 小批量添加 | 3–6人日 | 事件型用户占比及完成收益 |
| 长期承诺前 | A06 可恢复备份 | 先2–4人日方案PoC，再估实施 | 文件/图片恢复完整与平台可达；不是2–4天就能交付云同步 |

建议第一轮只选“入口＋默认构图＋必要的照片样式＋导出可靠”，然后观察两周。不要一次上完8项，否则难以判断是哪项带来收益。

## 7. 产品定位、差异化与商业化

### 7.1 推荐表达和不推荐表达

推荐用于测试的表达：**“把自己的日常照片，轻松贴成一块可回看的生活收藏板。”** 辅助说明是“一张照片就能开始、不用写长文、先帮你排好、想怎么摆再微调”。如果质量和时间未实测，不在宣传中承诺“一秒完美抠图”或“一分钟必定完成”。

不建议主打“又一个功能齐全的手账”“独家AI抠图”“永不丢失”“完全离线不上云”。前两项缺乏差异化依据，后两项不符合当前存储和处理链路。毛毡审美可做识别，不当技术或市场壁垒。

### 7.2 逐步形成的优势

可验证的优势顺序：少步骤得到满意作品 → 自己的素材越积越方便 → 回顾能唤起事件 → 作品与数据稳定可拥有。模板、记忆库复用和恢复能力应围绕这条路径发展。无需为了模仿大型竞品建立社区、明星IP或海量贴纸商城。（综合推断，中）

### 7.3 付费判断

目前没有本产品付费证据。查到的价格只作参考：念念手帐描述列月18元/年98元；拾片页面列终身会员38元；Day One官网列Silver 49.99美元/年、Gold 74.99美元/年。这些地区、能力、购买项、活动与服务成本不同，不能直接照搬，也不能证明其付费转化率。（M01/M06/M11；事实高、价格可变）

| 可能的收费对象 | 判断与边界 |
| --- | --- |
| 精选主题/模板/输出样式 | 适合先测“结果值不值得买”，不先建设素材商城 |
| 超出免费额度的高成本处理 | 有成本依据，但应先测基础额度能否完成价值；不用复杂金币任务挡住第一次保存 |
| 云备份/多设备能力 | 需有真实长期需求、持续服务和恢复责任；不能只收钱而无可靠性 |
| AI长文日记/风格图 | 与目前核心任务未必一致，待用户主动提出后验证 |

基础内容读取、已保存作品与普通导出不宜被突然锁住。暂不建议在选图→处理→保存主流程插屏广告；这属于产品取舍建议，不是声称整个市场排斥广告。

一次性收费适合成本可控的样式权益；持续云存储/大量推理应按实际资源设计，不能承诺低价终身无限。微信内收费、广告和对应主体/系统规则需在实际商业方案形成后核验，本轮不设计绕行支付路径。

### 7.4 成本示例：用户市场存在也可能不盈利

假设100个MAU，每人每月使用10天、每天处理3张、可计费尝试系数1.1：共3,300次。按腾讯通用抠图公开单价0.02元/次，处理费约66元/月，尚未计存储、流量、网关、运营和人力。（M12；单价与算术高置信度，全部行为参数为假设）

若其中2%付费、价格假设9.9元/月，收入仅19.8元；5%付费则49.5元。此例不是收入预测，也不是定价建议，只说明免费处理量、付费率和成本必须一起验证。当前自托管模型成本结构是机器与运维，不能直接套用每次0.02元，应按真实账单/负载比较。

因此不建议先追求大量注册再考虑成本，也不应在没有留存时从竞品订阅价推算营收。可观察“每周重复使用且至少有一次满意作品的用户”对应的处理成本，再讨论盈利。

## 8. 如何把“看起来有市场”验证成真实证据

### 8.1 最小研究：12次访谈＋30人两周使用

这是建议计划，不是已经完成的调查；本轮没有发送招募、消息或邀请。参与者应以非朋友、真实目标行为为主，记录来源；访谈补贴可用于访谈时间，不能按记录次数、分享次数付奖励后再声称自然留存。

**访谈12人建议组成**：6名轻量记录者、3名周末整理者、3名有现成工具的手账用户。重度用户用于理解替代，不让他们的高级功能需求代表所有新手。请用户展示自愿提供的最近行为，不索取隐私照片。

访谈重点：

1. 最近一次拍照后想整理是什么时候，后来如何处理？没有整理的具体原因是什么？
2. 现在用什么工具，最近实际完成了什么？花多少时间？为什么没继续？
3. 选3张自己的非敏感照片，用当前小程序完成一张板；观察卡点，不边操作边教。
4. 让用户在现有办法与本产品间完成同类任务；询问最终为什么选某个结果。
5. 哪些内容必须保留原背景、日期或一句话？是否曾因补记限制放弃？
6. 下次会在什么具体场景打开？如果不用，原工具哪一点已经足够？
7. 记录丢失/换机风险如何影响选择？如有付费经历，问实际购买及原因，而不是只问“愿不愿意付费”。

“喜欢这个点子”“觉得很可爱”“愿意试一下”只能作兴趣反馈；自己的照片完成任务、非提示再次使用、主动回看和实际选择替代才是更强证据。

### 8.2 三个先行实验

| 实验 | 操作 | 主要指标 | 失败说明 |
| --- | --- | --- | --- |
| 定位/场景实验 | 用同一产品能力呈现“日常三件”和“周末片段”两种招募页；不夸大未上线功能；渠道尽量匹配 | 来源明确的独立访问→体验申请→实际开始→完成 | 点击多、完成少可能是文案好奇或路径问题，不能算需求成立 |
| 毛毡/纸面偏好实验 | 同样照片、同构图、同清晰度，盲选两种风格并追问使用场景；顺序随机 | 成品偏好、是否愿用自己照片制作 | 若毛毡并无明显偏好，说明材质不应承担全部定位 |
| 自动构图实验 | 8–12人交叉完成当前手动版与辅助排版版；先用可交互原型或人工辅助验证 | 任务时间、手动操作数、满意度、最终选择 | 若只快却更不满意，需改构图或面向爱制作人群；小样本不声称统计显著 |

如使用人工辅助，明确记录为人工/原型实验，不把它当线上自动功能。先验证结果价值，再承担批量处理、复杂 AI 的开发成本。

### 8.3 两周使用的指标、分母和门槛

首轮30人应是**实际打开并开始体验的符合条件用户**，不是把未打开邀请也混在分母里；同时单独报告邀请→开始的流失。退出、失败和不再使用都保留在30人里，不通过剔除不活跃者提高留存。

以下数字是内部继续/停止投入的候选门槛，**不是行业基准，不代表统计显著**；试验开始前固定，不在结果出来后改口径。

| 指标 | 明确定义 | 首轮候选门槛 |
| --- | --- | --- |
| 首记完成 | 使用自己的照片，保存并能重新打开一张真实板；排除演示素材 | ≥20/30；否则先查入口、网络、质量和保存 |
| 首次满意 | 在全30人中，首张结果评分≥4/5且愿意保留 | ≥16/30；不只在成功者中问满意 |
| 首记耗时 | 从点击开始到首张可保存结果，报告中位数/P90与未完成数 | 中位数目标≤60秒；网络错误单列，不从总完成率隐藏 |
| 首周重复创作 | 第2–7天在另一天新增自己的记忆，不仅打开或调旧图 | ≥8/30；有提醒/无提醒分列 |
| 第二周重复创作 | 第8–14天至少一次新增或一次新的事件作品 | ≥6/30；若主要事件型使用，继续跟到下次事件 |
| 主动回看 | 排除当次编辑/导出，在另一天打开旧板/旧记忆 | 单列人数与次数，不强行要求每人分享 |
| 作品拥有/传播 | 保存相册成功、主动拉起分享、用户自述公开发布分别统计 | 不把接口success当作真实发送；不混成一个“分享率” |
| 替代选择 | 期末能指出具体场景下改用本产品，而非仅说好看 | 至少收集5个有真实行为支撑的独立案例 |
| 价格信号 | 透明展示尚未实施的候选方案，用户选择/预约；准备就绪后再做真实交易验证 | 预约与实际付费分开；不因勾选愿意就宣布盈利成立 |

6/30等小样本结果受个体影响很大。首轮用于发现问题；达到候选门槛后，至少扩大到约100名不同来源目标用户，再观察4周、分渠道与场景复核。朋友圈熟人支持和单个创作者传播不能单独代表稳定市场。

### 8.4 如何根据结果修改方向

| 观察结果 | 建议决策 |
| --- | --- |
| 首次完成低，流程/网络失败多 | 先修可用性，不据此认定市场无需求，也不追加花哨功能 |
| 首次很喜欢，但不同日期几乎不再记录 | 优先看场景频率和输入负担；不先用打卡奖励制造使用 |
| 周末/旅行作品反复出现，日常很少 | 收敛为事件型照片拼贴，提升补记/小批量；用事件复用评估，不执着DAU |
| 用户花很多时间布置且享受过程 | 自由制作可能是价值；保留手工模式，与快记录分开，不一律替用户自动化 |
| 用户只导出一张便离开，也不在下一事件回来 | 可能是一次性做图工具；按工具价值重新评估获客和付费，不包装成日记留存 |
| 有持续创作/回看，但担心丢数据 | 将可恢复备份提前，不以更多颜色作为替代 |
| 不愿替代任何原工具，持续使用和结果偏好都弱 | 缩小投入，回到目标人群/场景；不靠扩大功能清单挽救 |

## 9. 获客与传播：先证明渠道能带来有用的人

首轮可测试原创作品示例、手账/照片整理兴趣群的合规招募、校园或小型创作社群，以及用户自愿分享后的朋友体验。渠道选择是待验证假设；本轮未获得小红书搜索量、话题增长或同类小程序获客成本，不声称它们“正在爆发”。不未经授权发群消息或联系博主。

内容可先测试三种：同一张普通照片到成品的过程；三件日常物件的一天；旧周末照片整理回顾。使用有权分享的素材，展示实际可达步骤；比只展示一张精修宣传图更能验证期待和实际的一致性。

衡量：每个来源的去重访问、开始体验、首记完成、首周重复创作与真实成本。点击/点赞/收藏和作品保存分别记录；以“获得一位一周后仍在创作的用户的成本”比较渠道，不只比较扫码注册数。先人工按来源登记/小样本观察，后续若接分析，仅记录必要行为事件，不采集原图和记忆正文。

分享卡片可以保持轻量品牌识别，若后续加入小程序码或入口要验证权限、画面和接受度；不强迫公开日记，不把拉新作为继续查看自己记录的条件。（建议，中）

## 10. 推荐执行路线与当前取舍

### 10.1 第一轮该做什么

1. 明确只先争取轻量照片记录者，准备真实照片质量、存储和正式网络基础。
2. 做12次问题/任务访谈，先查首次入口和现有替代行为。
3. 验证“入口更直接＋默认构图＋完整照片样式”；必要时用小原型，不先开发全部提案。
4. 招募30名目标用户做两周真实使用；分别看日常与事件型任务。
5. 用重复创作、主动回看、替代选择和成本决定下一步；存在长期使用后再选备份和付费方案。

这是范围收敛建议，不需要为了市场验证重写原生架构。已有主题板/分类/四角工具可继续作为能力基础，暂不扩成复杂手账平台。

### 10.2 必须先确认的项目问题

- 首要目标是用户留存、短期盈利，还是课程/比赛展示？
- 是否已有非朋友真实用户、可读取的使用数据或允许访谈的现有人群？没有就从招募开始，不填虚假市场结论。
- 团队愿先押注日常记录还是事件整理？建议先两个小组比较，再确定，不同时服务所有人。
- 是否接受将“默认排版、历史补记、可恢复备份”的优先级提高？它们是新建议，需更新产品基线。
- 可投入多少研究时间/预算、能否提供真实手机和测试服务？没有正式提取链路时，应将人工原型结果和产品实测分开。

**当前建议：保留毛毡与照片物件，减少首次编辑负担，把“做出满意成品、方便第二次记录、能够可靠回看”排在装饰数量和泛功能之前。市场机会需要通过这条短路径验证，不能由已有代码数量或竞品热度直接宣布成立。**
