# P1 体验增强开发与验收

更新日期：2026-10-14。已完成 P1-01 至 P1-07 的开发接入：布局撤销重做、图层调整、图片裁剪修正、更多颜色纹理、分类筛选、微信图片分享，以及主题板、跨板复用与仅移除摆放。现有 100 项自动测试及微信官方模板编译通过，既有四组功能验收完成；本次导航白屏修复重新通过导航专项和完整添加/编辑/导出/月历回归。分享接口在自动验收中使用替身，没有实际向好友发送；真机发送与接收方查看待验收。新增交互仍需实际手机确认，P0 正式 HTTPS 部署与最终异常验收继续独立记录。

## 使用方式

打开某天毛毡板，进入编辑模式。板下显示“撤销”和“重做”；选中物件后，在记忆操作区显示“置顶”和“置底”。没有可撤销或重做的步骤时按钮禁用；物件已在最前或最后时，对应层级按钮禁用。

撤销、重做和层级调整后自动保存。返回浏览、首页或导出时，读取同一份已保存的布局。

调整图片：点击板上物件进入记忆详情，在“贴入毛毡板的物件”旁点击“裁剪 / 修正”。拖动四角改变裁剪范围，拖动框内移动选区，也可选比例、旋转或镜像。点击顶部“保存”或底部“保存到原物件”，成功后自动回到详情。

切换底色与纹理：打开某天板面并进入编辑，在下方“毛毡板面”卡片选择颜色，再点击纹理小样。色块与纹理名称带有选中标记，卡片右上显示当前组合；选择后自动保存，也可使用板下的撤销、重做。

分类查找：首页底部点击“分类查找”查看全部时间的记忆；月历中点击“按分类查找本月记忆”，带入当前正在查看的月份。可以切换分类、全部时间或指定月份。点击物件进入详情，点击日期旁“查看整板”打开当天完整板面。

直接分享：板面浏览模式点击“导出 / 分享这一天”，待作品生成后点击“分享到微信”，在微信面板中自行选择发送对象。也可以继续使用“保存到相册”。接收方看到的是完整板面图片。

主题收藏：首页点击“主题板”，新建并命名，从“记忆库”选择不同日期的物件。也可以在记忆详情点击“放入主题板”，选择已有主题或“创建并放入”。主题板使用同一套拖动、旋转、层级、材质、撤销和整板导出工具。

移除与恢复：选中板上物件后点击“仅移除摆放”，照片和文字仍在记忆库。主题板可重新添加；每日板通过“从记忆库放回当天物件”恢复当天的物件。需要彻底删除时，从记忆详情进入“彻底删除记忆”，确认后才会删除所有板上的引用。

## P1-01 布局撤销与重做

| 规则 | 实现 |
| --- | --- |
| 支持范围 | 拖动位置、缩放、旋转、毡面底色、毡面纹理、置顶与置底 |
| 记录单位 | 一次拖动在松手后记一步，每次有效的变换、换色或层级调整记一步 |
| 历史长度 | 最多保留最近 30 步，通过 `core/config.js` 的 `historyLimit` 配置 |
| 无效操作 | 仅选中物件、选择相同底色、重复置顶已在最前的物件等不增加步骤，也不清除可重做记录 |
| 分支规则 | 撤销后产生新的有效调整，会清空原来的重做分支 |
| 保存失败 | 屏幕布局和历史保留，持久草稿尽可能保存；可重试，也可继续撤销，不能误报已保存 |
| 会话边界 | 完成编辑、离开页面后重开、成功添加/移除摆放或删除记忆后重置历史；历史不跨小程序重启保存 |
| 详情往返 | 只修改文字、分类或替换照片且布局未变化时，可保留当前页面的布局历史；撤销不会回退这些记忆内容 |
| 外部变化 | 返回时发现板面或物件集合已变化，重新建立历史基准，避免撤销恢复已删除物件 |
| 草稿恢复 | 恢复未保存布局可记为一次调整，允许撤销回原来已保存的布局 |

撤销只处理布局，照片添加、替换、裁剪修正、删除以及文字修改使用各自的保存与确认规则。布局历史不持有照片文件，不阻止已删除图片的安全清理。

## P1-02 物件置顶与置底

- “置顶”把选中物件放到所有物件前面，“置底”把它放到最后面。
- 只改变层级，不改变坐标、尺寸、旋转角度、照片引用、所属日期及加入时间。
- 其他物件之间的相对前后关系保持不变；排序同时兼容旧数据中的相同层级值。
- 新增物件继续默认放在最前；层级调整支持撤销和重做。
- 浏览、编辑、首页预览和导出使用同一排序。重叠点击仍优先命中最上层物件。
- 月历仍按加入时间及固定 ID 选取前两个物件，置顶或置底不会更换月历预览。

照片处理和草稿恢复期间禁止布局调整。触发撤销、换色或层级操作时，会取消尚未结束的板面拖动，避免旧手势在之后覆盖新布局。

## P1-03 手动裁剪与基础图片修正

| 能力 | 实现与边界 |
| --- | --- |
| 编辑来源 | 默认“当前物件”，可切换“原始照片”重新开始；切换会提示放弃当前未保存的变换。使用原图会保留原图背景，不重新调用主体提取服务 |
| 裁剪 | 自由、1:1、4:3、3:4；四角 44px 手势区域，框内移动选区；选区始终在图片范围内，固定比例拖动保持比例 |
| 旋转与镜像 | 每次顺时针旋转 90°，水平镜像；选区跟随变换保留同一部分内容，旋转固定比例时宽高比例对应交换 |
| 重置 | “重置本次”恢复当前编辑来源的完整范围与初始方向；已保存的裁剪不能通过布局撤销回退，完整原图始终可重新选择 |
| 图片输出 | 本机 Canvas 生成透明 PNG，不把预览棋盘格、遮罩、选区线或角标写进图片；最长边不超过 2048px，小图不放大 |
| 保存 | 用户明确点击保存后提交；原图路径、文件内容、文字分类、所属日期、加入时间和完整 Placement 保持不变，主体图路径与尺寸更新 |
| 页面同步 | 保存后详情、板面、首页、月历和整板导出使用新主体图；详情标注“已手动调整”，之后替换照片会清除该标记 |
| 保存异常 | 先写新文件并确认图片可读，再原子更新记录；失败保留旧记录与当前页面调整，可重试保存；未提交的新文件安全清理 |
| 取消与冲突 | 返回时可放弃未保存调整；页面卸载取消未提交任务，延迟复制回调也不会误写。编辑期间照片被替换或记忆被删除时拒绝覆盖 |

本轮为矩形裁剪和方向修正。复杂边缘涂抹、恢复被自动提取误删的局部区域、亮度色彩修图仍不属于本轮实现；当前可切换原图重新裁剪，精细主体修复保留在 P2。图片调整草稿只保留在当前页面，未保存离开不跨重启恢复。

## P1-04 更多毡面颜色与纹理

| 类型 | 选项 |
| --- | --- |
| 原有底色 | 燕麦米 `#D9CBAF`、鼠尾草 `#C3D0BD`、暖灰 `#D4D0C8` |
| 新增底色 | 藕粉 `#DDC7C1`、雾蓝 `#C4D2D6`、奶油黄 `#E6DABB` |
| 细绒 `fine` | 默认纹理，沿用旧版本的细小纤维效果 |
| 长绒 `long` | 较长的弯曲纤维，交叠深浅线条 |
| 交织 `cross` | 交错的短纤维与浅色织纹 |

- 颜色和纹理分别选择，共 18 种组合。配置分别保存在每块每日板或主题板中，新板仍默认燕麦米与细绒，不继承其他板的选择。
- 三个纹理小样显示当前底色，使用生产渲染器绘制同一纹理的局部放大图。点击小样或下方名称都能选择；加载照片、处理照片与恢复草稿的相关操作继续遵循编辑状态限制。
- 首页预览、板面浏览/编辑及整板导出共用同一纹理绘制函数。纤维位置固定，不随刷新重新随机生成；纹理裁切在内毡面，不覆盖木框。
- 换色、换纹理只更新 Board 外观，不改变照片、文字、物件坐标、尺寸、角度、层级或加入时间；月历的记忆排序和数量保持原规则。
- 有效选择自动保存，支持撤销重做；重复选择当前项不增加历史。保存失败保留已保存快照与未保存草稿，可恢复草稿或重试保存。
- 旧 Board/草稿没有 `texture` 字段时按 `fine` 读取，读取不写入或迁移存储。第一次保存时写入纹理字段；旧版默认板面的像素与新默认纹理一致。未知纹理值会被数据校验拒绝，损坏快照不会被静默覆盖。

本轮没有新增纹理下载或远程资源依赖。真机长绒/交织的细节、拖动时的流畅度以及不同屏幕下的小样点击仍待设备验收。

## P1-05 分类筛选

| 规则 | 实现 |
| --- | --- |
| 分类 | 全部、饮食、自然、出行、日常、心情、未分类；复用详情页已有分类，不要求历史记录补齐 |
| 时间范围 | 全部时间或指定年月；月历入口默认当前查看月份，首页入口默认全部时间；不查询未来记录或月份 |
| 组合筛选与数量 | 分类和月份取交集；分类按钮上的数量统计所选时间范围，切换分类仍可看到其他分类数量 |
| 排序与分页 | 日期从近到远，同一天按加入时间从新到旧、相同时按固定 ID 排序；每页最多 20 件，按日期分组，仅向视图发送当前页缩略图路径与短文字 |
| 返回与更新 | 返回保留时间范围、分类和页码；分类修改、删除或照片替换后重新读取已保存数据；最后一页为空时自动收回到有效页码 |
| 完整板面 | 分类只影响查找列表；“查看整板”仍展示当天全部物件，保留原布局和层级 |
| 空状态与异常 | 无结果可清除分类或查看全部时间；完全没有记录时可记录今天；图片缺失显示占位且仍能进入详情；读取失败可重试，不覆盖存储 |
| 数据边界 | 查询、切换条件、翻页和浏览空月份不写入记录或创建每日板；未保存的详情草稿不参与筛选；退出后重新打开按入口重新初始化条件 |

本轮实现已有固定分类的查找，不包含全文搜索、自定义标签或云端查询。

## P1-06 微信直接分享

| 规则 | 实现 |
| --- | --- |
| 分享内容 | 使用作品预览对应的同一个本地 PNG，源图为 1800×1200，含完整木框、当前毡面和已保存的物件构图；微信发送后的压缩与显示效果以手机实测为准 |
| 接收方体验 | 接收的是图片，可直接查看整板；不提供指向发送方本地日期、图片路径或记忆 ID 的小程序卡片链接，不需要新增云端存储 |
| 入口 | 原导出页增加“分享到微信”；点击后立即调用 `wx.showShareImageMenu`，由用户在原生面板完成操作；不自动选择联系人或发送 |
| 小程序入口 | 显式传入 `needShowEntrance: false`，避免新版微信默认附带入口；作品图片中也不添加二维码或额外水印 |
| 兼容 | 检查 API 函数与 `wx.canIUse`，运行时不支持也显示相册替代路径；实际可选项由微信版本及环境决定，页面不承诺所有客户端均有相同菜单 |
| 状态 | 生成、打开分享面板、保存相册互斥；重复点击不重复调用。打开面板或收到接口成功回调，都不显示“发送成功”，也不修改相册保存状态 |
| 取消与失败 | 取消后保持预览，不显示错误；调用失败保留图片并允许重试或保存相册。分享错误与相册权限提示分别保存 |
| 图片失效 | 分享、保存及预览前同步检查文件；文件失效时禁用图片操作并显示“重新生成”。重新生成成功后可再次分享，原始照片及已保存板面不变 |
| 离开页面 | 页面卸载后的异步回调不再更新页面或弹出成功提示；空板、未保存布局、图片读取失败均不提供可分享结果 |

接口依据：[微信官方 API 类型与注释](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)，对应 [showShareImageMenu 官方文档](https://developers.weixin.qq.com/miniprogram/dev/api/share/wx.showShareImageMenu.html)。该 API 从基础库 2.14.3 起提供；入口参数从 3.2.0 起提供，3.8.2 起默认显示入口，因此这里显式关闭。实现以能力检测为准，不只比较版本号。

本轮为完整作品图片的直接分享。可交互的云端公开板、共享编辑与跨设备同步仍属于后续独立能力。

## P1-07 主题板、跨板复用与仅移除摆放

| 规则 | 实现与边界 |
| --- | --- |
| 主题管理 | 首页进入主题列表，新建、重命名、确认删除；名称去除首尾空格后为 1–30 个字，最多 50 块主题板 |
| 记忆复用 | 一条 Memory 可以放入多块主题板；照片、文字、分类和原始记录日期共用，不复制照片文件或生成新的记忆 |
| 独立布局 | 每块板分别保存 Placement 的坐标、尺寸、角度、层级，以及板面颜色和纹理；修改一块板的布局不会改变其他板 |
| 选择入口 | 从主题板选择已有记忆，支持跨日期、分类和月份查找；已有物件标记“已在板上”并禁用；新增后返回原板并选中 |
| 每日板规则 | 每日板只可放回原属于当天的记忆；跨日期收集使用主题板，原记录日期不变。新照片仍从每日板记录 |
| 数量限制 | 同一记忆在同一块板最多摆放一次；每日板、主题板各最多 30 件，满板有提示 |
| 详情联动 | 详情显示当前被多少块板引用；修改文字、分类、替换或裁剪主体后，各板引用同一份内容，各自布局保留 |
| 保留未摆放记忆 | 即使移除最后一处摆放，记忆、原图和主体图仍保留，可在分类查找中找到并重新放入板面 |
| 首页与月历 | 今日板、最近日期和月历只统计每日板上的摆放；主题复用不会增加当天记录数或伪造新日期 |
| 导出与分享 | 主题板沿用完整板体 Canvas 渲染，实际生成 1800×1200 PNG；预览显示主题名称，名称不写进作品图片 |
| 保存失败 | 创建并放入、添加、移除、重命名、删板和彻底删除均以一次原子快照写入；失败保留原内容，创建表单可重试 |
| 草稿与历史 | 添加/移除后重置布局历史；摆放版本检查防止旧草稿恢复已移除物件，甚至“移除后重新添加同一记忆”也会使旧草稿失效。目标板有未保存布局时先提示保存 |

三种删除操作的范围明确区分：

| 操作 | 入口 | 删除范围 | 保留内容 |
| --- | --- | --- | --- |
| 仅移除摆放 | 板面编辑中选中物件 | 当前板的一处 Placement | 记忆、照片、文字及其他板的摆放 |
| 删除板面 | 主题列表 | 该主题板及其布局 | 全部记忆、照片、文字及其他板 |
| 彻底删除记忆 | 记忆详情 | Memory 与所有板上的 Placement，图片进入安全清理流程 | 系统相册原照片和其他记忆 |

三种操作均有确认提示，不通过布局撤销恢复。每日板不可作为主题板删除；移除过物件的历史每日板仍可从记忆库放回当天记忆。

本地快照内部版本升为 v2，继续使用 `felt-journal:v1` 存储键。读取 v1 时先按旧版完整关系校验，再仅在内存中升级；读取、筛选不会写回。第一次成功修改才原子写入 v2，失败不覆盖旧快照。原有 Memory 的 `boardId` 保留为来源日期字段，不能再用于判断唯一所属板；实际摆放关系以各 Board 的 `placements` 为准。

主题列表封面取最多三个物件作摘要；打开板面和导出展示真实布局。主题收藏仍为本地功能，不包含云同步或多人共同编辑。
